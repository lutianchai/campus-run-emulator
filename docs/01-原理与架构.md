# 原理与架构

宿主机 zsh 入口协调模拟器、adb、Python 轨迹/传感器进程及 Java 空间切换工具。运行数据均生成在本机，发布内容仅为源码、自有 APK 和明确列出的 GNSS 资产。

定位通过模拟器控制台的 geo fix 注入，需要本机控制台认证令牌。只有应用实际申请定位时，GNSS 才会消费位置。GPS定位调试入口通过 adb emu 发送单个点；连续轨迹及传感器脚本使用本机 5554 控制台连接，因而假设单个默认端口模拟器。

GNSS 补丁以 bind mount 覆盖 `/vendor/bin/hw/android.hardware.gnss@2.0-service.ranchu`，设置 SELinux 标签后重启服务。脚本校验替换后的文件哈希。此挂载不跨重启持久化，不等于修改磁盘里的原始驱动。

Android 多用户拥有各自应用数据。Java 工具实现最小 ADB 协议，在设备本机连接 root adbd；切换及应用启动整条命令链保持连接打开。空间不是安全沙箱：宿主机与 root 可访问其数据。

网络探测包含 DNS 和客机到 www.baidu.com:443 的 TCP 连接；只探测该目标，不保证其他业务服务器可用。部分长时运行故障可能出现在模拟器网络转发层，重启是现有恢复策略。
